# Reproducibility

Two artifacts pin the peira environment so a run can be reproduced
exactly. They are the Python lockfile and the Docker image. Both are built from
the same pinned inputs and both are verified in CI.

## Python lockfile

`uv.lock` in the repo root is the single source of truth for every
pinned Python dependency. It is generated by
[uv](https://docs.astral.sh/uv/) from `pyproject.toml` with one
command.

```bash
uv lock
```

It covers the base package plus every optional extra (`dev`, `hf`,
`openai`, `anthropic`, `google`, `all`). The base tier has zero
third-party runtime dependencies by design and AGENTS.md protects
this invariant. Hashes for all packages, including the torch CUDA
wheels, come from index metadata, so the full-extras set is
hash-pinned with no multi-gigabyte downloads at lock time.

The `pip install peira` path is unchanged. The package metadata stays
PEP 621 with the maturin backend, so plain pip installs from
`pyproject.toml` build the extension automatically. Installing from
PyPI uses prebuilt abi3 wheels (no Rust toolchain needed); installing
from an sdist or git URL builds from source and needs a Rust toolchain.
uv manages the lockfile only and never replaces pip as the installer.

### Installing from the lockfile

For day-to-day work and CI, install with pip as usual.

```bash
pip install -e .[dev]
```

For a tamper-evident install pinned to the lockfile, export the
lockfile to a hash-pinned requirements file and install it with
`--require-hashes`. This is what the Dockerfile does.

```bash
uv export --frozen --format requirements-txt --no-emit-project --extra dev -o /tmp/pinned.txt
pip install --require-hashes -r /tmp/pinned.txt
pip install -e . --no-deps
```

`--require-hashes` makes the install tamper-evident. pip refuses any
wheel whose hash is not in the exported file. `uv.lock` is a
universal lock covering every supported platform and Python version.
CI installs it on CPython 3.12.

### Regenerating

After changing dependencies in `pyproject.toml`, run one command.

```bash
uv lock
```

To upgrade everything within the declared constraints.

```bash
uv lock --upgrade
```

Commit `uv.lock` in the same PR as the `pyproject.toml` change. CI
runs `uv lock --check` and fails the PR when the lockfile is stale.
Reviewers check that the diff only touches the intended packages.

## Docker image

`Dockerfile` is a multi-stage build:

1. **rust-builder** (`rust:1.98.1-slim-bookworm`, matching
   `rust-toolchain.toml`): compiles the optional PyO3 accelerator
   (`peira._core`) from `crates/peira-python` against the pinned
   `Cargo.lock`.
2. **runtime** (`python:3.12-slim-bookworm`). It projects `uv.lock`
   to a hash-pinned requirements file at build time with `uv export`
   and installs it with pip `--require-hashes`. Then it installs peira
   editable from the `/peira` checkout (editable is load-bearing, since
   the CLI resolves dataset paths from the repo root relative to the
   package files), copies the built `_core` extension next to the
   package, and ships the versioned datasets so trial runs work out of
   the box. Runs as a non-root `peira` user with `peira` as the entrypoint.


### Build

```bash
docker build -t peira:local .
```

With the full adapter extras (Hugging Face + LLM baselines):

```bash
docker build -t peira:local --build-arg EXTRAS=all .
```

### Run

```bash
docker run --rm peira:local run --adapter mock --suite trial --seed 0 --out /tmp/runs
```

Exit 3 is the expected result: the run completes but the 100-case
Trial sits below the ranking floors, so it is ranking-ineligible (the
same convention the README quickstart documents).

To persist artifacts outside the container, mount a volume:

```bash
docker run --rm -v "$PWD/runs:/home/peira/runs" peira:local \
  run --adapter mock --suite trial --seed 0 --out /home/peira/runs
```

### What the image contains and what it does not

The image contains the peira package at the built commit, its
pinned Python dependencies, the compiled Rust accelerator, and the
datasets as committed. It does not contain API keys (pass them with
`-e`), the private holdout (never baked into any image), or a pushed
registry tag. Images are built, never pushed. Registry pushes stay
manual until an external reproducibility request asks for one.

## CI

`.github/workflows/docker-build.yml` builds the image on every push
to main and every PR, then smoke-tests it: the Rust extension must
import and the mock trial run must complete. The job is build-only.
Nothing leaves the runner.
